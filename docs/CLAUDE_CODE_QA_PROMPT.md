# Запрос на проверку рабочего функционала и вёрстки Valuon (для Claude Code)

Скопируй текст ниже целиком и запусти в Claude Code внутри папки проекта (`cd valuon && claude`).

---

## Промпт

Проведи функциональный и визуальный QA-прогон проекта Valuon — статический сайт (HTML/CSS/JS, без сборки) с бэкендом Supabase. Цель: найти сломанный функционал (кнопки/ссылки/формы, которые не реагируют на клик или делают не то) и визуальные поломки (наезжающие элементы, пропавшие стили, поехавшая адаптивная вёрстка), а не только явные краши.

Сначала прочитай `docs/ARCHITECTURE.md`, чтобы понять список страниц и их JS-модули, и `js/supabase-client.js` для конфигурации.

### Как проверять
Подними локальный статический сервер (`python3 -m http.server` или аналог) в корне проекта. Используй headless-браузер (Playwright, установи если нет: `npm install -D playwright && npx playwright install chromium`) и напиши короткий скрипт, который:
1. Открывает каждую HTML-страницу проекта (`index.html`, `register.html`, `login.html`, `reset-password.html`, `dashboard.html`, `receipts.html`, `business.html`, `verify.html`, `about.html`, `privacy.html`, `terms.html`, `roadmap.html`).
2. Собирает все ошибки консоли (`console.error`, необработанные исключения, `unhandledrejection`) и все проваленные сетевые запросы (404 на CSS/JS/шрифты/иконки/CDN-скрипты).
3. Находит на странице все интерактивные элементы (`button`, `a`, `input[type=submit]`, элементы с `onclick`/`addEventListener`-обработчиками, кастомные компоненты типа `custom-select`/`custom-datepicker`) и проверяет, что на каждый **реально повешен обработчик** — не просто существует в разметке, а либо есть слушатель событий, либо элемент — обычная ссылка с валидным `href`. Отдельно отметь кнопки, у которых `id`/`class`, ожидаемый в JS (`document.getElementById(...)`, `document.querySelector(...)`), не совпадает с реальным атрибутом в HTML — это самая частая причина "кнопка ничего не делает".
4. Кликает по каждой доступной без авторизации кнопке/ссылке (лендинг, формы входа/регистрации, переключение языка, переключение темы, открытие/закрытие модалок, мобильное меню) и проверяет, что видимое состояние страницы действительно меняется (открылась модалка, поменялся текст, произошла навигация) — а не просто "не было ошибки в консоли".
5. Для `dashboard.html` и `business.html`, где нужна авторизация: если тестового аккаунта нет, опиши в отчёте, что нужно создать тестовый Supabase-аккаунт (или дай инструкцию, как это сделать через Supabase MCP) и вручную/скриптом пройти по SPA-вьюхам (`dashboard-nav.js`) — переключение между "Мои вещи", "Чеки", "Уведомления", "Настройки" — и по всем модалкам добавления/редактирования/удаления вещи, выписки чека в business-панели.
6. Делает скриншоты каждой страницы на трёх ширинах: 375px (мобильный), 768px (планшет), 1440px (десктоп) — и явно проверяет: нет ли горизонтального скролла на мобильном, не наезжает ли текст на элементы, не обрезаются ли карточки/кнопки, видны ли все иконки (в том числе FontAwesome — если CDN не загрузился, иконки станут пустыми квадратами/пропадут), не съезжает ли футер/хедер, не перекрывает ли что-то модалку/тост-уведомление.
7. Проверяет обе темы (светлая/тёмная, `theme.js`) и оба языка (RU/EN, переключение через `*-lang.js`) на каждой странице — искать конкретно: элементы, у которых не применился перевод (остался ключ `data-i18n` вместо текста), и элементы, нечитаемые в тёмной теме (например, тёмный текст на тёмном фоне из-за захардкоженного цвета вместо CSS-переменной).

### На что обратить особое внимание (типичные причины "кнопка не работает")
- Обработчик события повешен один раз при загрузке страницы, а элемент затем перерисовывается через `innerHTML`/пересоздаётся динамически (например, карточки вещей/чеков в `dashboard-items.js`, `receipts.js`) — старый обработчик теряется, новый не навешивается (event delegation сделан неправильно или отсутствует).
- Скрипт подключён с `defer`/`async`/без атрибутов не в том порядке, из-за чего один модуль дергает функцию другого раньше, чем тот успел определиться — проверь порядок `<script>` тегов в каждом HTML относительно зависимостей (например, `supabase-client.js` должен грузиться раньше файлов, которые создают из него клиент).
- CSS `pointer-events: none`, `z-index` конфликт (невидимый элемент поверх кнопки перехватывает клик), `overflow: hidden` обрезающий кликабельную область.
- Кастомный `custom-select`/`custom-datepicker` рендерится поверх скрытого нативного `<select>`/`<input>` — проверь, что скрытый элемент не остаётся кликабельным поверх кастомного (двойной UI) и что при сабмите формы в реальный `<input>` действительно попадает выбранное значение.
- Условный рендеринг кнопки в зависимости от auth-состояния (`requireAuth`, `checkAuthOnHome`) — проверь race condition: не показывается ли на долю секунды неправильное состояние (кнопка "Войти" вместо "Личный кабинет" и наоборот) до того, как асинхронно придёт ответ Supabase.
- Формы, у которых `required`/`pattern`/`type` в HTML не совпадают с кастомной JS-валидацией (`login-lang.js` — кастомная HTML5-валидация) — проверь, не блокирует ли это отправку формы с корректными данными или наоборот пропускает некорректные.
- CDN-зависимости (jsPDF, Chart.js, jsQR, pdf.js, Turnstile, FontAwesome) — что произойдёт с конкретной кнопкой/страницей, если конкретный CDN недоступен (например, кнопка "Скачать PDF" при недогруженном jsPDF): падает молча или показывает пользователю понятную ошибку.

### Формат отчёта
Список найденного, сгруппированный по страницам, с указанием: что сломано, воспроизведение (какие шаги привели к поломке), вероятная причина в коде (файл + строка, если нашёл), критичность (🔴 полностью ломает флоу / 🟠 заметно, но есть обходной путь / 🟡 косметика). Приложи скриншоты проблемных мест, если формат ответа это позволяет. В конце — короткий список из 3-5 самых заметных для обычного пользователя поломок.
