## Промпт

Проведи полный аудит проекта Valuon на баги, ошибки и уязвимости. Это статический сайт (HTML/CSS/JS без фреймворков и сборки) с бэкендом на Supabase (Auth + Postgres + Storage + Edge Functions). Основные страницы: `index.html`, `register.html`, `login.html`, `reset-password.html`, `dashboard.html`, `receipts.html`, `business.html`, `verify.html`. Основная логика в `js/*.js`, стили в `css/*.css`.

Перед началом прочитай `docs/ARCHITECTURE.md`, `docs/PROJECT_BRIEF.md` и `docs/Valuon_Estonia_Backlog.md`, чтобы понять текущую архитектуру и уже известные (или уже исправленные) проблемы — не трать время на переоткрытие того, что уже зафиксировано, но обязательно **перепроверь**, действительно ли отмеченное как исправленное исправлено в текущем коде, а не только в документации (документация в этом проекте иногда отстаёт от кода).

Проверь по следующим категориям, для каждой найденной проблемы укажи: файл + строку, что не так, чем это грозит (пример эксплойта, если применимо), и конкретный фикс.

### 1. Безопасность / уязвимости
- XSS: везде, где пользовательский ввод или данные из БД попадают в DOM — через `innerHTML`, `insertAdjacentHTML`, шаблонные строки в разметке. Проверь `dashboard-items.js`, `receipts.js`, `business-panel.js`, `verify.js`, все `*-lang.js` (динамические переводы).
- Инъекции через QR-код / URL-параметры на `verify.html` — как парсится `?data=&sig=&pk=&id=` в `verify.js`, что будет, если в значениях встретятся `|`, `:`, `<`, `"`, переносы строк.
- Хранение и передача Ed25519-ключей — проверь, генерируется ли приватный ключ магазина сейчас на сервере (Edge Function `create-shop`) и точно ли нигде в клиентском коде (включая старые ветки/файлы) не остался путь, создающий или логирующий приватный ключ в браузере/localStorage/sessionStorage.
- RLS-политики Supabase — свериться с реальными политиками в проекте (через Supabase MCP/дашборд, не только с тем, что написано в доках) для таблиц `items`, `business_receipts`, `shops`, `shop_keys`, `profiles`: точно ли пользователь не может читать/писать чужие данные, точно ли нет открытых на `anon`/`public` ролях таблиц без RLS.
- Секреты в репозитории — `.env`, `supabase-client.js`, git-история (`git log -p -- .env`) на предмет закоммиченных ключей, особенно service_role key (не anon key).
- CDN-зависимости без SRI (jsPDF, Chart.js, jsQR, pdf.js, qrcode-generator, Cloudflare Turnstile) — оцени реальный риск supply-chain атаки и предложи, где SRI добавить дёшево.
- Rate-limiting и брутфорс — на login/register/reset-password, как реализовано в `security.js`, достаточно ли этого от локальных попыток подбора пароля/капчи.
- CSRF/open redirect — есть ли параметры redirect/next в auth-потоке, которые можно подменить.
- Валидация на сервере vs только на клиенте — везде, где форма валидируется JS в браузере, проверь, что то же самое проверяется в Supabase (RLS/constraints/Edge Function), а не только в UI (пользователь может обойти клиентский JS через прямой запрос к API).

### 2. Бизнес-логика / корректность
- Расчёт гарантийных сроков (`dashboard-items.js`) — граничные случаи: warranty_months = 0, отрицательные значения, дата покупки в будущем, часовые пояса при сравнении дат.
- Генерация и верификация Ed25519-подписи (`receipt-generator.js`, Edge Function `verify-receipt` если есть в проекте/Supabase) — совпадает ли canonical payload на этапе подписи и на этапе верификации побайтово (любое расхождение в сериализации сломает верификацию для части чеков).
- PDF-генерация (`receipt-generator.js`) — корректность парсинга числовых значений (уже был баг с этим, коммит `30e7246` — проверь, нет ли похожих мест в текущем коде), валюты, округления сумм.
- Множественная валюта — проверь, нет ли смешения валют в одном чеке/расчёте, корректно ли форматируется отображение.

### 3. Общее качество кода
- Дублирование Supabase-клиента между файлами — не рассинхронизировалась ли конфигурация.
- Необработанные промисы / отсутствие try-catch вокруг вызовов Supabase — что видит пользователь при обрыве сети или ошибке API.
- Мёртвый код / неиспользуемые функции после рефакторингов (особенно после удаления клиентского Ed25519Signer в `business-panel.js`).
- i18n — отсутствующие ключи переводов (уже частично зафиксировано в бэклоге как B-8), несовпадение ключей между RU/EN словарями.

### 4. Доступность и мелкие баги
- Модалки — фокус-трап, закрытие по Escape, `aria-*` атрибуты (`modal-a11y.js`).
- Кастомные компоненты (`custom-select.js`, `custom-datepicker.js`) — работа с клавиатуры, поведение на мобильных.

### Формат ответа
Дай итоговый отчёт в виде списка проблем, отсортированного по критичности (🔴 критично / 🟠 важно / 🟡 можно отложить), с указанием файла, строки и конкретного фикса для каждой. В конце — короткий список из 3-5 проблем, которые стоит закрыть до реального пилота с живыми продавцами.
